# Component-List Components #
Repeated child components.
Child item directories appear directly inside the component-list directory.
Use children-order.json to reorder list items.
componentListComponent describes what kind of item the list is expected to contain.
componentListItemLabel is a human-friendly singular label for add/edit prompts.
componentListBlocks holds the ordered child blocks.
componentListDefaultSortKey, componentListDefaultSortDirection, and componentListDefaultGroupKey define the default reader display.
componentListGroupCollapsedPreviewRem controls grouped virtual container preview height.
componentListGroupsExpanded controls whether grouped virtual containers are expanded by default.
Child item sortKeys are human-readable sort name/value pairs. Values may be strings or numbers.
Child item groupKeys are human-readable group name/value pairs. Values are strings.
Automatic values are defined by sortValueDefs/groupValueDefs on the item's reusable component definition, editable at /templates/components/NAME/definition.json.
Bind text or table cells using <!--hvy:sort-value {"key":"Fake Rank"}-->12<!--/hvy:sort-value--> or <!--hvy:group-value {"key":"Fake Category"}-->Fake Blue<!--/hvy:group-value-->.
Group definitions support text and enum with string values. Enum source text is a configured label. Edit the source to change a bound value; derivedSortKeyNames/derivedGroupKeyNames track the materialized item keys and must not be hand-authored as replacements for source edits.
In the UI, select item text (including text nested inside an instance) and choose Use as… → Sort: [key] or Group: [key]. Choices include shared definitions and the owning item's existing manual keys. Choosing a manual key creates its automatic definition and binds the selection: groups use text, numeric sorts use number, and other sorts use text. Existing explicit definitions always retain their configured type. Choose Create sort key… or Create group key… for a new key or to configure a manual key's type explicitly. Date sorts require a format; enum creation accepts one label per line and initially uses each label as its stored value. List settings also let you create definitions, rename keys, change types, and edit enum labels/values. Automatic sources require a reusable component item type; merely opening the menu does not change definitions or manual values.
Numbered component-list slots are sorted by numeric suffix, with file order only breaking ties.
Plain Markdown before the first numbered slot is treated as the first implicit child block.
Grouped reader display renders virtual container components using componentListGroupsExpanded as their default state; they are not serialized and do not appear in children-order.json.
